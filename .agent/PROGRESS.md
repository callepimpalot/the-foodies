- [x] **AI Week Planner Chat — built, tested live by the user, and iterated to completion:** resolved the brief's four open questions (hybrid library/generated dish sourcing with a visible source badge; recipe/leftover/note days all independently lockable; overwrite warning instead of silent clobbering or auto-locking; chat-stated date sub-range defaulting to the visible 7-day window), then built it — `src/lib/weekPlanChat.js`, `src/hooks/useWeekPlanChat.js`, `src/components/WeekPlanChat.jsx`, shared `src/lib/saveRecipe.js` extracted from Capture. This session's Browser pane could never reach the user's local dev server (confirmed architectural — my sandboxed Browser tool and the user's own machine are different networks; `localhost` never means the same thing to both), so verification happened entirely through the user testing on their own phone/browser and reporting back, live, across several rounds:
  1. Confirmed the core flow works — describe a week, get a proposal, follow-up refine.
  2. Found a **real correctness bug**: a follow-up mentioning one day ("on Wed I want a salad") collapsed the entire week down to that single day. Root cause: the "narrow to a stated date range" rule (meant only for the first message) was firing on every turn, and the client trusted whatever date set Gemini returned. Fixed with an explicit first-turn-vs-follow-up prompt distinction plus a client-side guarantee the date set can never shrink after the first turn — the deeper fix (never trust the model, only the client's own record) also turned out to be needed for locked-day content, which had the same class of bug (only the `locked` flag was protected, not the content).
  3. Added drag-and-drop-to-reorder days on request — first attempt used the HTML5 Drag and Drop API, which doesn't work on touch at all (iOS unsupported, Android unreliable); replaced with Pointer Events; that still failed because the touch target was smaller than the project's own 44px minimum; replaced entirely with a tap-to-pick-up/tap-to-swap interaction, which then didn't swap because `swapDays()` — a side effect — was called from inside a `setState` updater, and React.StrictMode double-invokes updaters in dev, silently swapping then swapping back. Three real bugs, three real fixes, each confirmed by the user re-testing.
  4. Added on request: "Add a day" to extend past the initial 7-day window (an `empty` day type, fillable by dragging content onto it); an empty-day action sheet (plan from library / leftovers / single-day-scoped AI chat / note); and a recipe inspect+refine sheet (`RecipeDaySheet.jsx`) — servings stepper, live-scaled ingredients, a refine-chat reusing `refineRecipe()`, and "Lock In This Day" which commits the customization onto just that day (never the shared library recipe) and auto-locks it.
